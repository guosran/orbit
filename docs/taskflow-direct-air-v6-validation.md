# V6 direct AIR validation

Latest outcome: real NPU runs pass overcapacity generic GEMM/add-scale,
all-dimension tiling, separate M/N boundaries, and the formerly failing K-only
and all-M/N/K-tail cases. Real M5/D2048/I11008 SwiGLU passes three seeds and 15
full output sets. M128/D2048/I11008 compiles and is submitted to the NPU but
returns a runtime timeout without numerical output; M128 completion remains
unestablished. Every earlier named failure below is retained history; r12 is
the final successful boundary attempt.

The v6 fixtures are generated by `test/TaskflowAIR/prepare_v6.py` from explicit
Taskflow source tests. Dimension substitution happens before compilation and
never rewrites compiler-generated AIR. The independent NumPy reference uses
float64 equations and casts only the final result to f32. No reference function
runs as an execution fallback.

`test/TaskflowAIR/prepare_exp_probe_v6.py` adds exp accuracy inputs in [-80,80]
and SiLU inputs in [-103,103], including near-zero values, multiples of ln(2),
and the f32 exponential saturation region. Each of three seeds permutes every
probe input independently. Standalone exp is kept inside its finite normal
output range. These tests do not extend the approximation contract to NaN or
infinite inputs. They require explicit `--approx-exp`.

The fixture set contains GEMM M16/K128/N64 (45,056 full-buffer bytes), generic
add-scale M64/N64 (65,536 bytes including its intermediate), and four-task
SwiGLU with M5 and M128, D2048 and I11008. SwiGLU inputs are uniform [-.5,.5];
weights use the same distribution scaled by inverse square root of their fan-in.
The first element of every input is zero. Fixture metadata preserves measured
reference gate/hidden ranges. Weight scaling keeps magnitudes stable as the
reduction size grows; these are f32 arrays and all elements participate.

## Capacity boundary

The installed npu2 target model reports 65,536 bytes of local memory per compute
tile and 524,288 bytes per memory tile. Its full model has 8 columns and 6 rows;
this is not a claim that every column is available to one runtime partition.
The compiler's 24,576-byte payload budget is a conservative policy, not the
physical local-memory total. The executor reserves 4,096 bytes for the stack.
Runtime state, alignment, locks and actual buffer allocation must also fit;
the final installed AIR allocator/linker remains authoritative. Local evidence
`results/orbit-direct-air-v6/capacity-facts.json` under the aie-toy project binds
the installed model/header and package versions.

## Reproduction and evidence

`run_taskflow_direct_air_v6_case.sh` takes a prepared input directory and a fresh
output directory. It hashes the native compiler executable, preserves exact
source/config, captures native lowering logs, and passes emitted AIR directly
to installed `aircc`. For tiled plans, temporary storage buffers are appended
to the host ABI in compiler storage order. They are system-memory XRT scratch
BOs and are not described as persistent AIE SRAM. The C++ compiler owns every
phase, tile, dependency, DMA region and arithmetic decision.

```bash
cd /home/shiran/project/orbit
source /home/shiran/project/aie-toy/scripts/env.sh
python test/TaskflowAIR/prepare_v6.py --case gemm --m 16 --k 128 --n 64 \
  --output /absolute/NEW-inputs
bash scripts/run_taskflow_direct_air_v6_case.sh \
  --input /absolute/NEW-inputs --output /absolute/NEW-output \
  --target-config /absolute/config.json --distribute-initialization
```

For clean-shell reproduction, run the wrapper through
`env -i HOME=/home/shiran PATH=/usr/bin:/bin LANG=C.UTF-8 bash --noprofile --norc`.
A config can request `{"generic_air":{"tile_sizes":[4,8,32]}}`; these are bounds
for source loop dimensions after optional generic initialization distribution.
The wrapper does not contain a mapping algorithm.

Each seed uses two retained warmups and three measured executions. The harness
records actual XRT submit/wait events and compares every output against the
external reference using atol=rtol=1e-5. The independent auditor reopens saved
arrays and checks source/ELF hashes and runtime events. Input/reference hashes
are saved per seed. Compile and execution failures remain in their original
output directories, with no CPU/Triton compiler fallback and no installed-package
modification. The existing runner is imported from the Triton-XDNA package only
to dispatch the native AIR ELF through XRT; its Triton compiler is not called.

## Observed probes and retained failures

`exp-clean-shell` and `silu-clean-shell` under the v6 result root completed on
NPU from an empty shell environment. Each has 3 seeds and 15 saved output sets
that pass the independent 1e-5 absolute/relative audit. Exp maximum relative
error over normal outputs is 2.91366e-7; normalized L2 is 2.70724e-8. The large
absolute error (2.47589e27) occurs at exponentially large outputs. SiLU maximum
absolute error is 1.90735e-6, normalized L2 4.57201e-9. Its negative saturation
tail can flush to zero, so relative error there reaches one. This does not
establish relative accuracy in the underflow/saturation tail. Independent
float64 metrics and hashes are saved in `math-probe-independent-metrics.json`.
The first probe executor's f32 reference norm overflowed for exp; the independent
metric calculation corrects that diagnostic and the executor now uses float64
for both norm operands. Original outputs/results remain preserved.

`add-scale-hardware` (8 phases) fails the installed AIR conversion with
`aie.mem op has more than 16 blocks` and a dominance error. Four phases in
`add-scale-four-hardware` compile and run but produce zero output and fail the
numerical check. Neither is reported as correctness success.

`gemm-hardware-six` compiles, then its first real run returns XRT
`ERT_CMD_STATE_TIMEOUT`. Its generated `air_project/aie.input.air.mlir`
independently reveals a lock cycle: the first MM2S BD waits for two produced
lock counts, the first initialization phase releases one count, and the next
initialization phase waits for a free lock already consumed by the first.
This diagnoses a shared-buffer lock-combining problem in the installed AIR
conversion. The generated AIE, compiled ELF, logs, failure record and failed unsupported XRT
report request are retained. No post-generation lock patch was applied.

The v6 executor checkpoints observed submission events immediately before each
XRT wait, preserving evidence if a future kernel times out. This file write is
included in the host wall-time boundary. The reported values are diagnostic
end-to-end latency, not compute-only timing or a speedup claim.

The final compact per-task emitter establishes the capacity milestone:
`add-scale-compact-four-r3` passes all 15 output sets for the 65,536-byte generic
source, retaining its full-size temporary in a device BO between two firmware
stages. `gemm-compact-no-k` passes all 15 sets for the 45,056-byte GEMM source
using tiles [16,16,128] and the source's original initialization/reduction order.
Independent final linker ledgers report 24,576 and 16,384 payload bytes in the
two add-scale stages, and 17,408 payload bytes in the GEMM stage. Each reserves
4,096 additional stack bytes. These figures come from emitted linker addresses,
not a repetition of the planner's estimates. Each graph has one actual host
submission. This is correctness/capacity evidence, without a speedup claim.

The reduction-split variant `gemm-compact-six-r3` compiles and runs after the
loop-token fix but fails numerically. The M5 real-size compact SwiGLU compilation
in `ffn-m5-compile-first` is rejected by the installed deadlock routing verifier
in its three GEMM stages. The verifier identifies a packet-flow receiver/core/
MM2S/S2MM cycle. Its suggested unsafe override is not applied. These remain
explicit failures, distinct from the successful overcapacity cases.

`search-archive-alternating-hardware` measures three accepted candidates from
the original C++ `--search --backend=air` archive. The initial mapping is
[16,16,128]; accepted neighbors are [8,16,128] and [8,32,128]. An oversized
[16,32,128] neighbor remains explicitly unsupported. Each accepted archive's
actual `taskflow.mlir` is lowered separately, and the comparator binds archive
candidate ID, Taskflow, native plan, AIR, ABI and final ELF hashes. Three seeds,
two retained warmups and three hot forward/reverse rounds check 45 output sets;
all pass the independent auditor. Per-seed medians for the three variants are
9.367578/9.333048/9.371798, 9.323369/9.337529/9.393577, and
9.401197/9.436216/9.420466 milliseconds. These differences establish no speedup
on the unlocked machine, and the theoretical model remains uncalibrated.

The initial M128/D2048/I11008 compact SwiGLU compiles to a real AIR ELF in
107.47 seconds (`ffn-m128-compile-first`). This distinguishes the successful
M128 compilation from the M5 routing rejection. A compiled ELF alone is not
numerical execution evidence; the actual run status is retained alongside it.

The separate `exp-edge-hardware` experiment deliberately includes expected f32
infinities and subnormals, and the unchanged finite-output harness marks it
`numeric_failed`. `classification.json`, generated by
`classify_exp_edges_v6.py`, independently classifies all 15 saved output sets.
Exp(-103), exp(-100), exp(-88) and exp(-87.8) flush expected subnormals to zero;
exp(-104) is zero in both. Normal finite reference points have maximum relative
error 6.14010e-8. At input 88.72283935546875, the approximation returns a finite
value while the reference rounded to f32 is infinity. Inputs 88.8, 90 and 103
produce infinity in both. This diagnoses saturation behavior and establishes no
IEEE guarantee at the overflow boundary. Neither tolerances nor finite checks
were relaxed to make this diagnostic pass.

`swiglu-edge-hardware` explicitly evaluates SiLU(gate) times up for 45 pairs:
gate {-103,-90,-10,-1,0,1,10,90,103} crossed with up {-1e6,-1,0,1,1e6}.
All 15 independently audited sets pass the unchanged 1e-5 absolute/relative
check; maximum absolute error is .0625 on large-magnitude outputs. This is an
activation stress probe, not a replacement for full-size FFN execution.

`ffn-m128-fused-r5` compiles the actual M128/D2048/I11008 source and makes one

`_24`, `_27`, `_33` in that order. Thus the all-M/N/K non-divisible hardware case

The case wrapper supports the planned channel legalization path only when a
native `hardware_stages[].legalize_channels` flag requests it. It preserves
canonical DMA AIR, then invokes installed `air-opt` with `--air-dma-to-channel`,
`--canonicalize`, and generic printing. Installed `aircc` subsequently runs
its dependency pipeline for the first time; earlier attempts that pre-ran
dependency/hoisting remain recorded separately.
The native compiler applies its checked channel resource allocation through
`--legalize-air-channels`; a separate `--check-air-channels` invocation audits
the result. Each command, executable absolute path/SHA256, log, return status and IR hash is retained, and
`aircc` compiles the pinned artifact. Python invokes these tools without
rewriting IR or deciding resources. Cases without the compiler flag use their
original direct path. Execution outcomes for this path require their own fresh
artifacts; merely preparing it establishes no new numerical success.

The installed standard DMA-to-channel conversion is an explicitly trusted
compiler step, not a formal equivalence proof. The native post-conversion
checker verifies its planned resources and the integrity of the converted IR;
independent hardware/reference checks validate the resulting observed behavior.

`audit_channel_ports_v6.py` independently inspects final emitted AIE IR when
channel legalization is requested. It follows `aie.dma_start` ports through BD
block chains and correlates physical buffers with compiler-preserved storage
views, checking every requested stage/storage/direction against the native
port table. This is static final-IR resource evidence, not hardware event
tracing or measured on-wire traffic. Any inability to correlate a buffer is a
failed audit rather than an inferred match. Legalization does not authorize
additional transfers or payload; canonical and pinned native plans retain the
same declared traffic and tile storage requirements.

Channel-path attempts remain separately named. `gemm-k-tail-pinned-r7` fails a
native fingerprint round-trip check before installed compilation. In r8, the
native legalization/check succeeds for K-only and all-tail cases, while
installed `aircc` rejects generated `scf.parallel` reductions. R10 adds installed
standard `--canonicalize` before pinning and uses fresh native storage origin
metadata; native legalization and independent checks again pass, but installed
`aircc` rejects an operand dominance violation during its optimization pipeline.
Thus r7/r8/r10 establish no new compiled or numerical success. The case wrapper
records each installed conversion command/executable hash and every native
check, preserving both pre- and post-conversion IR. The pre-device validation
path will audit final compute ports and exact local-payload bounds when a
future attempt reaches compiled AIE; it does not submit a known resource
mismatch to the device.

R11 uses the direct standard conversion route and omits static L1 deallocation
only for native stages that require this resource legalization; the arena is
owned by the complete stage and its full payload remains accounted. K-only
r11 reaches generated AIE and its independent static port audit confirms A
full/tail buffers on compute S2MM0 and B full/tail buffers on S2MM1, with C on
MM2S0. Compute-only buffer declarations total 11,424 bytes, exactly the native

The static AIE resource audit is distinct from successful final linking or
numerical execution.

Numerical reference comparisons and NPZ result serialization run after the
latency interval; they are excluded. Only the small pre-wait event checkpoint
is serialized inside that interval.
The alternating comparator records wait events in memory and serializes after
timing; it does not write the case executor's pre-wait checkpoint. Artifact
boundary labels distinguish those measurement paths.
