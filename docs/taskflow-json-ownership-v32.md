# Native tile configuration ownership repair (v32)

The real four-assignment pilot in `full-joint-v32-r1/preparation-r4` admitted the all-CPU plan but returned `tile_sizes requires positive integers` for all three assignments containing NPU work, although its configured tile sizes were positive. The failure was before native planning, not unsupported source arithmetic or physical infeasibility.

A standalone program linked only against the pinned `LLVMSupport` reproduced the cause: parse a JSON object, erase `generic_air.tile_sizes`, then copy the enclosing value. Erase reported success and the key was absent, but the copy resurrected that key with an already destroyed array, eventually producing `Unknown kind`. The pinned `ObjectKey::operator=(const ObjectKey&)` retains its old owned string when assigned a borrowed DenseMap tombstone. DenseMap copying then reconstructs the old owned key instead of preserving the tombstone, and copies the destroyed mapped value. This is reproducible without MLIR or ORBIT; the frozen vendor dependency was not modified.

`Taskflow/JSONUtils.h` now derives configurations by recursively rebuilding owned objects, arrays and strings while filtering fields. Object iteration skips tombstones. All JSON-object erase sites in the Taskflow library were replaced, including native cost stripping, source tile precedence, evaluator/domain identity derivation, reuse pricing and chosen-plan canonicalization. The native child materializer also treats a selected source tile attribute as authoritative over inherited configuration tiles. Caller configuration remains unchanged.

Validation:

- `json-ownership.cpp`: six checks, including remove/copy, nested tombstones, nested arrays, owning borrowed strings and preserving the caller.
- Enhanced inactive-binding contract: nine ON checks, including an inherited tile of 16 and an explicitly selected tile of 8 producing two real native phases.
- Real four-assignment pilot: before, one feasible export and three unknown refinements; after, four feasible selected exports and zero unknown feasibility results. All four costs remain unknown because this pilot has no complete calibrated cost model. Exhausting these four assignments is not a hardware or latency optimum proof.

CPU-only evidence is under `/tmp`: `v32-json-erase.cpp` and `.log` preserve the standalone failure; `v32-json-ownership-test.log` records the independent regression; `v32-tile-config-test.log` records the native tile contract; `orbit-pilot-tile-before-v32` and `orbit-pilot-tile-fixed-v32` retain the real pilot receipts. No old experiment output, vendor file, NPU state or Git history was changed.

The same filtering repair also covers Neura's exact-score cache `stage` field and the retimer's four superseded body-binding receipt fields. Both affected C++ sources were rebuilt in the complete ON default build. All 35 lit tests passed. The nearest common-parent retimer runner initially stopped before exercising the retimer: its old fixture claimed a 2×2 mapper tile for a 1×1 CGRA, while `mapper-arch-4x4.yaml` specifies a 4×4 tile per CGRA. Only those fixture dimensions were corrected to 4×4; production shape validation was preserved. The runner then passed its positive and six negative controls, emitted the retimer JSON, and confirmed the four obsolete fields were absent with the common binding verified. Original failure evidence remains in `/tmp/orbit-json-neura-retimer-on-v32`; corrected evidence is `/tmp/orbit-json-neura-retimer-on-fixed-v32`.
