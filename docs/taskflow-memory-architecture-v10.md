# Target memory architecture and execution boundaries

A program candidate combines its Taskflow computation and dependencies with resource, schedule and data-copy choices. The target owns the resources and connectivity. The common layer continues to use `StaticResource`, `StaticMemory` and `StaticTransfer`, with `StaticResourceDomain` describing system/device/tile ownership. Ownership does not imply accessibility. A memory can list individual compute resources; that list takes precedence over the legacy device-level access list. A buffer is an allocation in a memory instance, not a memory instance itself.

`validateMemoryArchitecture` checks identities, acyclic domain ownership, capacities, accessors and directed transfer resources. `findMemoryPath` checks directed reachability without requiring bandwidth or latency. The whole-task copy adapter filters layout, dtype, byte-range and scratch constraints before selecting a shortest legal path. It materializes each hop as a transfer and location copy, with creation/use dependencies. Shared copies count once. Cost remains uncalibrated when a used path has no calibrated or explicitly synthetic parameters. The existing static-model parser retains its old cost requirements; the new architecture parser accepts topology with unknown costs.

The native adapter receives `generic_air.memory_architecture` and `generic_air.memory_binding`. Binding keys are `host_memory`, `local_memory`, `compute_resource`, `dma_resource`, `input_link`, `output_link` and `submission_resource`. Omitting both retains the existing target contract. Generic plans, copy allocations, events and lowering check the selected identifiers. `host_to_l1` and `l1_to_host` remain internal AIR channel-role names; they no longer define the public storage endpoints. Target binding selects the corresponding directed links. The current backend supports direct, row-major, unchanged-dtype links without extra scratch. It rejects a multi-hop AIR binding; multi-hop common planning is tested separately on the synthetic architecture.

The target also declares one serial logical host worker and a host submission resource. Only the host worker can directly compute on BO memory; NPU access is through the declared DMA links. This does not claim the host has a single physical CPU core. Backend binding rejects CPU resources mislabeled as NPU computation, wrong storage technologies and a local memory owned by another resource domain.

The actual NPU binding describes system-memory XRT BO tensor payload and the local tensor allocation pool accessible to the selected AIE compute resource, with explicit input/output DMA paths. AIR memory spaces remain backend facts: external=0 and local=2. The local payload policy stays at 24,576 bytes; the compiler's 4,096-byte stack reservation is separate. The logical pool does not assert a single physical SRAM bank: emitted linker scripts can place buffers in several bank windows. This contract does not claim that the entire physical SRAM is available for tensors, or model memtile SRAM as available capacity. Host BO capacity is represented as an unbounded policy (`INT64_MAX`), not a measurement of available system DRAM. BO reuse is host preparation, not weight residency in AIE SRAM. Downstream DMA/channel realization is audited separately from planned bytes; planned bytes are not measured DDR traffic. A flow endpoint audit cannot prove the intervening physical switchbox route or exclude undocumented firmware storage.

`GenericTargetCapabilities` supplies finite implementation and tile-alignment choices. Automatic search obtains the local capacity from the same checked target binding used by planning. Declared implementation subsets are enforced by planning as well as proposals. Candidate evaluation binds the full memory architecture and capability identity. Changing a link, resource accessor, capacity or model cannot silently reuse a prior evaluation.

`ProgramCommunicationPlan.executionRegions` records the currently supported single native program call. All input dependencies belong to the same region and share its one host-submission event on a target-declared submission resource. Compute and transfer events remain separate; device stages reference the checked execution groups, with one stage for the resident path. The checker requires complete event/stage coverage and one actual submission for this backend. It does not charge launch per incoming data edge. A prepared-call composite prediction owns the host submit, combined device wait and output return once; it is not summed with separate compute or DMA estimates. The CPU whole-task adapter has no implicit offload call boundary. Independent program fission continues to express repeated calls through its checked manifest; a single-call model does not become a calibrated whole-partition model.

The synthetic fanout regression describes a shared SRAM accessible by two compute resources and two local SRAM instances with precise access lists. A shared imported value transfers 64 bytes once for both consumers. Separate local copies transfer 192 bytes across the shared staging path (64 into shared SRAM plus 64 into each local SRAM). This is a CPU planning result, not a claim of NPU cross-stage sharing. The regression rejects unknown accessors, ownership cycles, inaccessible same-device local memory, capacity violations, topology mutation and missing paths. Existing version, lifetime, coverage and dependency negatives remain active.

Phase-local imports expire at each task boundary, including intermediate copies on a multi-hop path. Retention can instead share those transit copies across proved read-only consumers. On the same two-local-memory target the regression accounts for 256 bytes under phase-local policy versus 192 bytes with retained staging; compute-created and external source copies remain available under their own lifetimes. Transfer consumers participate in the lifetime/policy checker, so a hidden retained transit copy cannot be labeled phase-local.

Amoeba retains its actual grid/SRAM-placement implementation in `lib/Backend/Neura/Orchestration/orchestration_utils.cpp` (`assignAllSrams`) and its existing II predictor and scheduler. The common types can name those resource and SRAM instances, but this change does not invent SRAM byte capacities or transfer calibration absent from the architecture input, nor replace the production Amoeba mapper. Existing supplied static targets are validated through the shared architecture validator. Importing the physical grid's full SRAM topology is a future backend adapter; generic unknown costs remain unknown rather than borrowing NPU numbers.
