# Implementation-aware direct AIR cost contract

The opt-in `implementation-composite` provider evaluates one prepared complete-program command. It preserves the existing theoretical baseline, v9 `linear-composite` provider, exact `observed-table`, and CGRA models. Adding this interface does not supply calibrated coefficients or claim measured performance.

The four frozen features are `command_count`, `implemented_scalar_f32_product_operations`, `implemented_mixed8_f32_product_operations`, and `hardware_stage_count`. Product counts are logical source scalar operations assigned to the checked scalar or `scalar-product-vector-add-f32:8` implementation. They are not counts of native vector multiply instructions: mixed8 retains scalar products and vectorizes supported additions. Separate add/subtract scalar and vector-pack counts are available as diagnostics. The first model family covers f32 multiply/add/subtract only; division and exponentials remain outside its calibrated domain.

`command_count` sums positive submission counts from checked public execution regions. Device stages and input transfers do not create additional submissions. `execution_region_count` reports the number of these boundaries. The current provider requires exactly one submission; partitioned commands require separate calibration. The boundary is `prepared-command-host-to-host`, with prepared BO policy and observer identity bound through `target.runtime`. Coefficients describe a joint compute, communication, and runtime composite. No DMA-byte, per-edge launch, or separately predicted communication charge is added to the result, and coefficients must not be interpreted as independently measured physical components.

A model uses schema `orbit.direct-air.cost.v1`, kind `implementation-composite`, explicit `calibration`, model identity/version, training-manifest SHA256, target/toolchain/runtime identity, and the prepared-command boundary. `terms` contains exactly the four features above with finite nonnegative millisecond coefficients. Unknown calibration produces no value. A valid calibrated model outside its domain produces `out_of_domain` and a null value. Exact observations continue to use full execution fingerprints and status `measured`; they are not generalized by this provider.

The new `domain` requires `family_fingerprints`, `architecture_fingerprints`, implementation and source-operation whitelists, `allow_tails`, and integer `feature_ranges`. The source family erases static extents and source names while retaining task dependencies, argument/storage bindings, SSA operation structure, all arithmetic constants, affine access maps, loop nesting, lower origins and steps, storage dtype/layout/memory space, and the alias contract. It is a structural membership signature, not an execution key or a proof that every shape is calibrated. Architecture fingerprints bind the checked memory/link/resource description. Exact source fingerprints remain provenance but do not gate this model, allowing predeclared new shapes and tiles in the same family.

Mandatory numeric envelopes cover the four terms, source maximum loop extents on axes 0–2, actual maximum tile spans on axes 0–2, source phase count, DMA bytes, resident payload, local capacity, and cores per stage. Additional native integer facts may further restrict the domain. `allow_tails=false` rejects nonuniform source/tile tails. Static affine unit-step loops and exact supported mixed8 lane coverage are required regardless of the envelope. An envelope does not override backend legality, memory checks, or implementation coverage. The new kind rejects exact-source range fields to avoid confusing a transferable structural domain with v9 source-specific guards.

Training and holdout configurations must be declared before labels are read. Check the native feature matrix rank before fitting the four composite terms: two implementation indicators with a single operation count can be collinear with the command term. Fit only successful, independently audited training observations. Heldout timings remain untouched until parameters and model identity are frozen. Correlated terms and host-wait quantization limit coefficient interpretation; heldout error and ranking uncertainty must be reported without refitting the same holdout.

The CPU cost test uses synthetic coefficients solely to check contracts, family distinctions, numeric-domain rejection, and accounting boundaries. It is not calibration evidence. Real experiment inputs, labels, parameter freezing, and measured results belong in the companion artifact repository.

The prepared-host policy is distinct from device residency. A reusable calibration identity can describe all ABI inputs staged on every call, temporary BOs reused as scratch, outputs copied back, and labeled hot calls following completed warmups; exact case/ABI/input identities remain separately bound experiment evidence. This policy does not assert that weights or caches remain resident in AIE SRAM. Likewise, the native target's 24,576-byte tensor-payload budget is a checked capability policy, with the compiler stack reservation accounted separately; it is not the tile's total physical SRAM capacity.

The common whole-task CPU adapter is a separate consumer of source-derived versions, copies, and transfer paths. Under `phase-local`, every transfer-created copy is unavailable after its importing task, including intermediate transit copies on a multi-hop route; external copies and compute-created versions remain sources for subsequent tasks. The independent checker includes both transfer and compute users when enforcing that boundary. Under `retain-across-users`, a valid transit or consumer-location copy can supply several tasks and its creation transfer is counted once. The actual-MLIR fanout regression contrasts the same synthetic DRAM→shared→local0/local1 target: 256 transferred bytes for phase-local versus 192 for retention. These are CPU planning facts, not NPU measurements or evidence of cross-stage AIR residency support.

A three-term experiment ablation may use the same native provider with the hardware-stage coefficient fixed to zero and independently fit the remaining three coefficients. Each comparator is evaluated separately, with its own frozen identity; their predictions are never added together. The original theoretical sensitivity remains explicitly uncalibrated. Static design rank and conditioning, CPU contract tests, and numerical correctness do not establish heldout prediction accuracy or measured optimization benefits.

CPU-only adapter/checker fixes do not update an already frozen NPU compiler, plan, executable, or measurement identity. Rebuilding a library or checker does not necessarily change a statically linked compiler executable that does not reference that implementation. CPU regression evidence must record both compiler and checker executable identities separately; any device results remain attributable to their archived compiler and executable. The following experiment is separately identified and does not change these accounting or applicability contracts.


## Frozen experiment and heldout validation

The companion artifact experiment `results/taskflow/implementation-search-v10/` now contains a completed, separately frozen calibration and validation. `train-final-r1` supplies 12 configurations, three seeds, two warmups and five hot calls per seed: 252 numerically checked outputs and 180 hot labels. The four-term `frozen-model-final-r1/model.json` SHA256 is `cf551d480ba4fb617977ec0a53a89d56aa83e5bde2ebf4e3bd4dbb952fc0c1f7`. Its training-manifest digest binds the actual training profile, independent audit, invocation, case preparation, static design and target identity. The model and all three comparators' native predictions were frozen in `predictions-final-r1` before heldout execution; no heldout refit occurred.

`holdout-final-r1` covers six predeclared configurations: M32/K128/N64 with tile `[4,16,64]`, scalar or mixed8 and phase-local or panel retention; and M17/K129/N80 with tile `[8,32,32]`, scalar or mixed8 phase-local. Three seeds yield 126 numerically checked outputs and 90 hot labels. `heldout-validation-final-r1/validation.json` reports finite FP32 checks with atol=rtol=1e-5. Timing is prepared complete-command host wall under the recorded detailed observer and actually selected polling wait backend. It includes preparation, transfer/runtime/device wait and output return; it is not device cycles or a separate DMA measurement.

| Frozen comparator | Heldout MAPE | Maximum absolute relative error |
|---|---:|---:|
| Implementation-aware four-term composite | 1.6304% | 5.4624% |
| Independently fitted three-term ablation, stage coefficient zero | 2.6846% | 8.6393% |
| Original uncalibrated theoretical sensitivity | 96.4006% | 96.6354% |

All predictions were obtained through the native C++ provider, with separate configurations for each comparator. The theoretical baseline retains its original uncalibrated coefficients and omitted runtime effects; its error is not a comparison against another hardware-fitted model. The four-term model's worst error is the scalar tail configuration, underestimated by 5.4624%; tail mixed8 is underestimated by 2.2278%. These six observations support this bounded experiment, not a claim of general predictive accuracy.

Within the two preselected heldout program groups, the four-term model chooses the observed median-minimizing mixed8 phase-local candidate, giving zero **descriptive point-estimate regret** in both groups. It nevertheless reverses the scalar phase-local/panel ordering once among seven within-program pairs. The three-term ablation ties phase-local and panel within each implementation: its M32 minimizing tie set has regret range 0–0.0543%, and its tail choice has zero regret. The theoretical model ties scalar and mixed implementations for equal structure; preserving these ties gives M32 regret range 0.0543–7.2748% and tail range 0–11.1575%. These are candidate-set reports, not proof that production search found a global optimum; ties are not broken retrospectively using measurements.

The M32 mixed8 medians are 17.312491ms phase-local and 17.321891ms panel, a 0.009400ms gap; scalar medians are 18.662296ms and 18.571938ms, a 0.090358ms gap in the opposite residency direction. These differences are small compared with the observed sample dispersion, and paired samples have both signs. No statistically significant or causal retention benefit is established. The model's positive stage coefficient is a composite fit: retention changes traffic as well as stage count, so this coefficient does not isolate physical stage overhead. The implementation-specific logical-product slopes likewise include correlated additions, memory operations and runtime effects; the command coefficient is an intercept because every training command count is one.

The frozen acceptance envelope includes **predeclared heldout static features**, never heldout timing labels. Inclusion in that envelope is not training coverage. In particular the tail's 15 device stages extrapolate beyond training's 2/3/5 stages, even though they are allowed by the model domain. New sources still require the same structural family, supported arithmetic and implementation, target architecture/runtime identity, and every feature guard. Complete FFN has a different family and includes unsupported exponential/division arithmetic, so this GEMM→scale calibration remains out of domain for full FFN; no scalar or mixed FFN latency is inferred from it. Existing CGRA models and their baseline contract remain unchanged.

The independent explanation audit in the companion repository, `.work/implementation-search-v10/heldout-cost-explanation-r1/`, verifies frozen identities and recomputes errors, ties and regret from the saved native predictions and measured hot medians. It performs no refit, new production prediction, significance test or device execution. The saved independent raw-output audit remains the numerical evidence.
